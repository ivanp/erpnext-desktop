# Serpy Appliance Offline Build Artifact Collection (`eng/lock`)

This directory documents the collection mechanism and layout for the Serpy offline appliance build (Phase 3 of the Easy Install Experience plan, U13–U16).

---

## Overview

The Serpy appliance build installs a headless Debian 13 (Trixie) virtual machine running ERPNext v16 on Frappe v16, Python 3.14, Node 24, MariaDB 11.8, and Redis 8.0.
In Phase 3, all build inputs are downloaded host-side into a content-addressed cache, packed into a transport disk (`cache.tar`), and installed inside the guest with the virtual machine's network restricted (`restrict=on`).

The U13 spike exercised each install mechanism from this cache and passed the 6-component version gate on a collection VM that still had internet. The restricted-network build proof is recorded in docs/results.md once it has run.

---

## Cache Directory Layout (`/srv/cache`)

When unpacked into the guest, the cache directory structure is:

```
/srv/cache/
├── debs/
│   ├── *.deb                     # 244 binary Debian packages (Trixie base + Sid Python 3.14 + MariaDB 11.8.3)
│   ├── Packages                  # Generated by apt-ftparchive packages .
│   ├── Packages.gz               # gzip -9 Packages
│   └── Release                   # Generated by apt-ftparchive release .
├── git/
│   ├── frappe.tar.gz             # GitHub commit archive, commit 6a329d068416768ec47ccd3326b9cc95a8d7bf99 (v16.31.0)
│   ├── erpnext.tar.gz            # GitHub commit archive, commit 11e0ba0a1c45f217e2e73e885f699102d06da325 (v16.32.3)
│   ├── pypika.tar.gz             # GitHub commit archive, commit 2c50e6142b2d61d2d243e466fdd5dc03b3d918f2
│   └── gunicorn.tar.gz           # GitHub commit archive, commit 54b59ca884c79dcf04d4882658a32bbaf17e999f
├── tools/
│   ├── node.tar.xz               # node-v24.2.0-linux-x64.tar.xz (SHA-256: 91a0794f4dbc94bc4a9296139ed9101de21234982bae2b325e37ebd3462273e5)
│   └── yarn-1.22.22.tgz          # Packaged via npm pack yarn@1.22.22
├── wheels/
│   ├── *.whl                     # 176 wheels covering bench env, serpy-tools, and build backends
│   │                             # (includes pre-built CPython 3.14 wheels for mysqlclient 2.2.7 and psutil 7.0.0)
│   └── *.tar.gz                  # Pinned source sdists as fallback
└── yarn-mirror/
    └── *.tgz                     # 954 npm tarballs for Frappe and ERPNext asset build
```

Total uncompressed size: ~3.8 GB.

### Running the Generator Locally

Run in a Debian 13 environment or container:
```bash
# In Debian 13 (Trixie):
sudo ./eng/lock/generate-build-inputs.sh --output config/build-inputs.json
```

### GitHub Actions Workflow

The `.github/workflows/generate-build-inputs.yml` workflow can be triggered via `workflow_dispatch` to regenerate `config/build-inputs.json` inside a clean `debian:trixie` container, upload the resulting JSON as an artifact, and validate it using `dotnet test --filter FullyQualifiedName~BuildInputsTests`.

## Reproducible Collection Procedure

Collection runs in a Debian 13 (Trixie) environment with internet access (either a container or a collection VM booted from `debian-base-20260819-2575.qcow2`).

### 1. Configure Pinned APT Repositories & Install Toolchain
```bash
export DEBIAN_FRONTEND=noninteractive
printf '%s\n' '#!/bin/sh' 'exit 101' > /usr/sbin/policy-rc.d
chmod 0755 /usr/sbin/policy-rc.d

# Mirror exact production snapshot sources and pins
rm -f /etc/apt/sources.list /etc/apt/sources.list.d/*.list /etc/apt/sources.list.d/*.sources
printf '%s\n' 'deb [check-valid-until=no] https://snapshot.debian.org/archive/debian/20260822T000000Z/ trixie main' > /etc/apt/sources.list.d/serpy-trixie.list
printf '%s\n' 'Acquire::Check-Valid-Until "false";' > /etc/apt/apt.conf.d/99serpy-snapshot
printf '%s\n' 'deb [check-valid-until=no] https://snapshot.debian.org/archive/debian/20260822T000000Z/ sid main' > /etc/apt/sources.list.d/serpy-python314.list
printf '%s\n' 'Package: *' 'Pin: release a=unstable' 'Pin-Priority: 1' '' \
  'Package: python3.14 python3.14-dev python3.14-venv libpython3.14 libpython3.14-minimal libpython3.14-stdlib libpython3.14-dev' \
  'Pin: release a=unstable' 'Pin-Priority: 1001' > /etc/apt/preferences.d/serpy-python314
printf '%s\n' 'deb [check-valid-until=no] https://snapshot.debian.org/archive/debian-security/20260822T000000Z/ trixie-security main' > /etc/apt/sources.list.d/serpy-trixie-security.list
printf '%s\n' 'deb [check-valid-until=no] https://snapshot.debian.org/archive/debian/20260822T000000Z/ trixie-updates main' > /etc/apt/sources.list.d/serpy-trixie-updates.list

install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://supplychain.mariadb.com/mariadb-keyring-2025.gpg -o /etc/apt/keyrings/mariadb-keyring.gpg
printf '%s\n' 'deb [signed-by=/etc/apt/keyrings/mariadb-keyring.gpg] https://archive.mariadb.org/mariadb-11.8.3/repo/debian trixie main' > /etc/apt/sources.list.d/serpy-mariadb.list
printf '%s\n' 'Package: mariadb-* libmariadb* libmariadbd* galera-4' 'Pin: origin archive.mariadb.org' 'Pin-Priority: 1001' > /etc/apt/preferences.d/serpy-mariadb

apt-get update -q
apt-get install -y git cron fontconfig qemu-guest-agent nginx supervisor python3-pip build-essential \
  libssl-dev libffi-dev libmariadb-dev libmariadb-dev-compat libxml2-dev libxslt-dev libjpeg-dev zlib1g-dev libcairo2-dev \
  redis-server=5:8.0.2-3+deb13u2 mariadb-server=1:11.8.3+maria~deb13
apt-get install -y -t sid python3.14=3.14.7-1 python3.14-dev=3.14.7-1 python3.14-venv=3.14.7-1
```

### 2. Collect & Index Debian Packages
```bash
CACHE=/srv/cache
mkdir -p $CACHE/debs
cp -a /var/cache/apt/archives/*.deb $CACHE/debs/

# Index with apt-ftparchive (present out-of-the-box in the base image)
cd $CACHE/debs
apt-ftparchive packages . > Packages
gzip -kf -9 Packages
apt-ftparchive release . > Release
```

### 3. Collect Node & Yarn
```bash
mkdir -p $CACHE/tools
curl -fsSLo $CACHE/tools/node.tar.xz https://nodejs.org/dist/v24.2.0/node-v24.2.0-linux-x64.tar.xz
echo '91a0794f4dbc94bc4a9296139ed9101de21234982bae2b325e37ebd3462273e5  '$CACHE/tools/node.tar.xz | sha256sum -c -
tar -C /usr/local --strip-components=1 -xJf $CACHE/tools/node.tar.xz
npm install -g yarn@1.22.22
( cd $CACHE/tools && npm pack yarn@1.22.22 )
```

### 4. Collect Git Repositories
```bash
mkdir -p $CACHE/git
git clone --bare https://github.com/frappe/frappe.git $CACHE/git/frappe.git
git clone --bare https://github.com/frappe/erpnext.git $CACHE/git/erpnext.git
git clone --mirror https://github.com/frappe/pypika.git $CACHE/git/pypika.git
git clone --mirror https://github.com/frappe/gunicorn.git $CACHE/git/gunicorn.git
```

### 5. Resolve Bench Env, Collect Wheels & Build Binary Wheels
```bash
# Set up tools venv
python3.14 -m venv /opt/serpy-tools
/opt/serpy-tools/bin/pip install --no-cache-dir frappe-bench==5.31.0 uv==0.11.33
ln -sf /opt/serpy-tools/bin/bench /usr/local/bin/bench
ln -sf /opt/serpy-tools/bin/uv /usr/local/bin/uv

# Init bench and fetch apps
useradd -m -s /bin/bash frappe
su - frappe -c "bench init --frappe-branch v16.31.0 --python python3.14 /home/frappe/frappe-bench"
su - frappe -c "cd /home/frappe/frappe-bench/apps/frappe && git checkout --detach 6a329d068416768ec47ccd3326b9cc95a8d7bf99"
su - frappe -c "cd /home/frappe/frappe-bench && bench get-app erpnext --branch v16.32.3"
su - frappe -c "cd /home/frappe/frappe-bench/apps/erpnext && git checkout --detach 11e0ba0a1c45f217e2e73e885f699102d06da325"

# Collect wheels
mkdir -p $CACHE/wheels
/home/frappe/frappe-bench/env/bin/pip freeze | grep -v '^-e' > /tmp/env-freeze.txt
/home/frappe/frappe-bench/env/bin/pip download --no-deps -d $CACHE/wheels -r /tmp/env-freeze.txt
/opt/serpy-tools/bin/pip download -d $CACHE/wheels frappe-bench==5.31.0 uv==0.11.33
/home/frappe/frappe-bench/env/bin/pip download -d $CACHE/wheels pip setuptools wheel build flit_core hatchling hatch_vcs setuptools_scm

# Pre-build wheels for sdists
/home/frappe/frappe-bench/env/bin/pip wheel -w $CACHE/wheels --no-index --find-links=$CACHE/wheels \
  docopt==0.6.2 googlemaps==4.10.0 mysqlclient==2.2.7 plaid-python==7.2.1 PyQRCode==1.2.1 rauth==0.7.3 psutil==7.0.0
```

### 6. Collect Yarn Offline Mirror
```bash
mkdir -p $CACHE/yarn-mirror
chown -R frappe:frappe $CACHE/yarn-mirror
printf 'yarn-offline-mirror "/srv/cache/yarn-mirror"\n' > /home/frappe/.yarnrc
chown frappe:frappe /home/frappe/.yarnrc

su - frappe -c "cd /home/frappe/frappe-bench/apps/frappe && rm -rf node_modules && yarn install --frozen-lockfile --ignore-scripts --ignore-engines"
su - frappe -c "cd /home/frappe/frappe-bench/apps/erpnext && rm -rf node_modules && yarn install --frozen-lockfile --ignore-scripts --ignore-engines"
su - frappe -c "cd /home/frappe/frappe-bench/apps/erpnext/banking && rm -rf node_modules && yarn install --frozen-lockfile --ignore-scripts --ignore-engines"
```

## Key Findings & Offline Build Adjustments (U13)

1. **`apt-ftparchive` is present in the base image:** `/usr/bin/apt-ftparchive` exists in `debian-base-20260819-2575.qcow2`. No pre-generated index needs to be committed to the repo; the guest can index itself.
2. **Flat APT Repository:** A single flat repository `deb [trusted=yes] file:/srv/cache/debs ./` holds all 244 packages (Trixie base, Sid Python 3.14, MariaDB 11.8.3). Pin files are unnecessary offline because only the pinned versions are in the cache.
3. **Drop `-t sid` offline:** `apt-get install -y -t sid python3.14=...` fails in a flat file repo because flat repos do not define named suites/codenames. Dropping `-t sid` works cleanly because the cache contains only `3.14.7-1`.
4. **Pre-built CPython 3.14 wheels:** `mysqlclient==2.2.7` and `psutil==7.0.0` compile cleanly against `libmariadb-dev` in Python 3.14. Pre-building `.whl` files into `$CACHE/wheels` ensures offline `uv pip install` or `pip install` needs zero external build-time network access.
5. **Yarn mirror permissions:** The mirror directory must be readable and writable by the `frappe` user (`chown -R frappe:frappe $CACHE/yarn-mirror`).
6. **Git `insteadOf` configuration:** Setting `/etc/gitconfig` with `insteadOf` rewrites `https://github.com/frappe/pypika` and `gunicorn` to local `file:///srv/cache/git/` bare clones, so `pyproject.toml` git dependencies resolve offline without code changes.

## Source pinning caveat

Frappe, ERPNext, PyPika and gunicorn are pinned as GitHub commit archives (`archive/<commit>.tar.gz`) by SHA-256. A re-fetch of two of them returned the same hash on 2026-11-21, but GitHub does not guarantee archive bytes are stable over time. When one changes, the checksum check fails closed and the generator must be rerun. The guest builds a local git repository from the unpacked tree, so `git rev-parse HEAD` there is a new commit, not the upstream commit hash: the upstream commit is pinned by the archive URL and its SHA-256, not by a git hash comparison.
